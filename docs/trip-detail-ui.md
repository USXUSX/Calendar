## 目的と対象

旅程詳細は、旅行中に全体の流れと未確定事項を素早く把握し、同じ流れから具体値の編集、AI指示、候補追加・判断へ進める画面とする。iPad mini縦向きでは実用的な情報量、iPad縦向きでは同じ構造のまま大きい文字と余白を優先する。

## 閲覧構成

- 全日程をcompact timelineとして縦に初期表示し、日単位では折りたたまない。
- 日付filterとカテゴリーfilterを同じ1行に置く。強いpill形状は使わず、小さい角丸と控えめな選択表示にする。
- 日見出しは `DAY`、日付、その日の主題、主要地点の天気・移動概要を表示する。日付は日別に色分けしない。
- 予定blockは `時刻 / カテゴリー / 本文` の対応を保つ。時刻とカテゴリーの間にtimelineの縦線を置かない。
- カテゴリーは文字色へ意味を持たせず、黒系の認識しやすい単色iconを使う。支援技術向けの名前を持たせる。具体的なiconと微調整は実装時に確定する。
- 場所名は予定タイトルへ自然に組み込み、青字と下線でlinkと分かるようにする。末尾の外部link記号は付けない。
- 通常コメントは本文より一段弱くても普通に読める濃さにする。予約条件、集合条件、締切等の重要コメントは、小さいlabel、文字色、太さで静かに強調する。
- 同行者コメントは旅程block内へ独立表示しない。

## 状態と候補

- 確定予定は状態装飾を付けない。
- 暫定、候補あり、未定は小さい角丸のbadgeで示す。
- 未定だけはbadgeに加えて左端へ短い色線を付ける。行背景は付けない。
- 候補は折りたたまず、`候補①`等の番号、場所link、同じ大きさの `OK / NG` を初期表示する。`OK / NG` は候補名の右側へ置き、投票数は表示しない。
- 候補追加は独立した長いbuttonにせず、`候補あり` badgeの右側に追加iconを置く。
- `OK / NG` は採用済み旅程をその場で変更する確定操作ではなく、後続変更に使う入力状態として扱う。

## 選択と編集

- 予定block全体を選択対象とする。hoverだけでは編集iconを表示しない。
- 選択中の1 blockだけ、右上に十分な大きさの編集iconを表示する。iconは選択枠線と重ならない位置に置く。
- 編集iconから専用の編集画面を開く。iPad miniでは下sheet、iPadでは右sideを基本とする。
- 編集画面では開始・終了、予定、通常コメント、候補と判断等の具体値を一つのまとまりとして扱う。
- 編集画面の下部に、対象予定へ紐づく任意のAI指示欄を置く。通常閲覧画面の上部には一括AI指示buttonを置かない。
- 保存、Validation、Direct Override、AI Patch採用等の内部方式は既存CAL境界を維持し、後続Phaseで契約化する。

## 後続Phaseで確定する事項

- 天気の取得元、更新時刻、失敗時表示と表示モデル
- UI状態としての暫定、候補あり、未定、通常・重要コメントの具体的な導出規則
- カテゴリーとiconの対応表
- 候補追加、`OK / NG`、AI指示の一時状態とライフサイクル
- 編集項目と意味ベースcommand / Direct Overrideの対応、保存前確認、Validation結果表示
- 外部評価値を旅程詳細へ表示するか
- コメント画面と予定編集内AI指示の最終的な役割分担
